Bottleneck Analysis
1. MatMul (48% of total time) - CRITICAL

Problem: Strided loads with 3136-byte stride

    Cache line is typically 64 bytes
    Each vector element from different cache line
    Memory bandwidth: ~50 GB/s wasted

Fix Priority: ⭐⭐⭐⭐⭐ HIGHEST
2. Softmax (9% of total time)

Problem: Scalar exp() inside vector loop

    Calling scalar function 10 times per iteration
    Function call overhead + scalar execution

Fix Priority: ⭐⭐⭐⭐ HIGH
3. BatchNorm (1.6% of total time)

Problem: Too many vector instructions (8 loads + 6 compute)

    Can reduce to 5 loads + 5 compute
    Or 4 loads + 4 compute with fused operations

Fix Priority: ⭐⭐⭐ MEDIUM
4. ReLU (0.2% of total time)

Status: Already decent at 1.98x

    Not worth optimizing further
    Already using efficient mask operations

Fix Priority: ⭐ LOW

// In gen_data.py, emit transposed weights:
emit_array("weights_transposed", model.weights.T.astype(np.float32))

// In C code: Use contiguous loads
void fmatmul_gemv_transposed(float *c, const float *a, const float *b_T,
                             const unsigned long int N, const unsigned long int P) {
    for (unsigned long int p = 0; p < P; p += vl) {
        vsetvli(vl, P - p, e32, m8);
        vmv.v.i v8, 0;  // accumulator
        
        for (unsigned long int n = 0; n < N; n++) {
            float a_n = a[n];
            // CONTIGUOUS LOAD: b_T[n*P + p : n*P + p + vl]
            vle32.v v16, (b_T + n*P + p);
            vfmacc.vf v8, a_n, v16;
        }
        vse32.v v8, (c + p);
    }
}

Phase 3: BatchNorm Optimization (Expected: 1.14x → 10-15x)
Reduce instruction count

Current: 8 vector instructions per iteration Optimized: 5 vector instructions
c

// Fuse operations:
// output = gamma * (input - mean) / sqrt(var + eps) + beta
// Rewrite as: output = input * scale + offset
// Where: scale = gamma / sqrt(var + eps)
//        offset = beta - mean * scale

// Precompute scale and offset once
vle32.v v_gamma, gamma;
vle32.v v_var, var;
vfadd.vf v_var, v_var, epsilon;
vfsqrt.v v_var, v_var;
vfdiv.vv v_scale, v_gamma, v_var;  // scale

vle32.v v_mean, mean;
vle32.v v_beta, beta;
vfmul.vv v_temp, v_mean, v_scale;
vfsub.vv v_offset, v_beta, v_temp;  // offset

// Then for each input:
vle32.v v_in, input;
vfmadd.vv v_in, v_scale, v_offset;  // in*scale + offset
vse32.v v_in, output;

Expected Improvement: 1.14x → 10-15x

    New cycles: ~50-70 (down from 628)

Phase 4: Additional Optimizations
A. Use LMUL effectively

Current: m8 everywhere

    Consider m4 for smaller operations
    Reduces register pressure
    Allows better instruction scheduling

B. Instruction scheduling
c

// Interleave loads and compute to hide latency
vle32.v v8, addr1;     // Load 1
vle32.v v16, addr2;    // Load 2 (while load 1 in flight)
vfadd.vv v8, v8, v16;  // Compute (while load 2 in flight)

C. Use vfrsqrt for 1/sqrt

If available on Ara:
c

// Instead of: vfsqrt + vfdiv
vfsqrt.v v_std, v_var;
vfdiv.vv v_result, v_in, v_std;

// Use: vfrsqrt (reciprocal sqrt)
vfrsqrt.v v_inv_std, v_var;
vfmul.vv v_result, v_in, v_inv_std;  // Faster!
